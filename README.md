# KsuNiMeet web — GitHub Pages + Supabase

Статический фронтенд KsuNiMeet на GitHub Pages, данные и realtime — в Supabase.
Это миграция работающего PHP-приложения (`../KsuNiMeet`) с VPS.

## Зачем и чего ждать

Исходный сервер — Apache + php8.3-fpm на VPS (Frankfurt). Ассеты уже ужаты
ниже 16 КБ и отдаются по HTTP/1.1, потому что с июня 2025 российские
провайдеры (ТСПУ) режут соединение после ~16 КБ.

**Известный риск, который эта миграция НЕ убирает:**

- **GitHub доступен в РФ нестабильно.** В мае 2026 OONI фиксировала рост
  неудачных подключений к GitHub с ~4 % до 10–16 %. Формального блокирования
  нет, но деградация реальная.
- **Supabase стоит за Cloudflare** («Cloudflare, our CDN provider» из их же
  блога), а сеть Cloudflare — именно то, что режут в РФ с июня 2025.
- У Supabase есть история региональных блокировок: ОАЭ (сентябрь 2025),
  Йемен (февраль 2026), Индия (февраль–март 2026). Платформа мультитенантная,
  поэтому блокировка одного проекта бьёт по всем.

Вывод: архитектурно это возможно, но доступность в РФ здесь скорее хуже, чем
у текущего VPS. Решение принято осознанно.

## Схема: что куда переехало

| было (PHP, JSON-файлы) | стало (Postgres) |
|---|---|
| `data/users/*.json`, `data/index.json` | `profiles` (+ `auth.users` для пароля) |
| контакты внутри пользователя | `contacts` |
| `data/chats/*.json` | `messages` (`chat_key` — пара uid) |
| `data/calls/*.json` | `calls` |
| `data/rooms/*.json` | `rooms` + `room_events` |
| `data/uploads/*` | `attachments` + Supabase Storage |
| `data/push/*.json` | `push_subscriptions` |

Вход остаётся «имя + пароль»: Supabase Auth требует email, поэтому он
синтезируется как `<username>@ksunimeet.example.com` и пользователю не
показывается.

Проверено на живом проекте, а не предположено:

- `@ksunimeet.local` Supabase отклоняет (`email_address_invalid`), и
  `ksunimeet.app` тоже — сервер требует, чтобы у домена была почта (MX).
  `example.com` эту проверку проходит и письма никуда не доставляет.
- Подтверждение почты в проекте ВЫКЛЮЧЕНО (`mailer_autoconfirm=true`)
  через Management API. Включённое подтверждение сделало бы вход
  невозможным: письмо на синтезированный адрес доставить некуда.

- `auth` переименовано в `auth_key` — на всякий случай, тоже служебное слово.

## Что нужно знать перед продолжением

1. Миграция применена через SQL Editor, поэтому таблица учёта миграций пуста:
   будущий `supabase db push` попробует применить файл заново. Файл написан
   идемпотентно (`if not exists`, `drop policy if exists`), но имейте в виду.
2. Пароль базы **неизвестен**: при создании проекта использован генератор
   Supabase, а значение из `.env.local` к нему не относится. Для доступа
   напрямую к Postgres пароль нужно сбросить в Settings → Database.
3. Access token `sbp_…` лежит в `.env.local` (в репозиторий не попадает).
   Он создан с полным доступом к аккаунту — отзовите или замените на
   scoped-токен, когда закончите.

## Экономия на круговых рейсах

Опрос раз в 1,2 с заменяется подпиской Realtime: сервер сам присылает новые
строки. Из PHP-версии исчезают `poll`, `me` и `msglist` как источники
постоянного трафика.
